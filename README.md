# 印刷套准复核台

接口把印张偏差放进待处理队列。另一个进程用行锁领走一条，算出套准或套不准后再写回。页面每隔一秒看一次，直到结论出现。

## 同名印张互斥门禁

同一印张名在队列中**互斥**：只要该名存在「待处理 / 领取中」编号，再次投递同名一律退回（HTTP 409），并点出冲突编号与解除条件；等在途编号出结论（套准/套不准）后自动解除，允许同名再开新一笔。

- 硬约束在服务端：PostgreSQL 部分唯一索引 `jobs_sheet_open_uidx on (sheet) where status in ('pending','running')`，并发同名投递也只会放进一笔。
- **重名门禁专页**（顶部导航进入）整页分三区：
  - 上区 ① 冲突监视：当前是否冲突、冲突编号列表、每个编号的解除条件、按印张名翻查的门禁流水；
  - 中区 ② 在途同名：待处理/领取中编号；出结论后此栏清空；
  - 下区 ③ 历史已结论：已出结论编号；同名再投时历史与在途分两栏展示。
- 只读账号（checker）看得到冲突与两栏清单，但没有投递入口，接口对其投递返回 403。仅靠提示框或总表标红不算门禁。
- 每次拦截与放行各记一条门禁流水（`gate_events`，动作 `blocked` / `admitted`），可在专页按印张名翻查。

## 启动

```bash
docker compose up --build
```

## 验收

1. printer 登录后稍等，封面-01 变成套准，内页-09 变成套不准。
2. 再送一条青偏差 0.5 的印张，状态先是待处理，随后变成套不准。
3. checker 没有投递按钮，但可进入门禁专页查看冲突与两栏清单。
4. 同名门禁：投「样张甲」进待处理，马上再投同名 → 被退回并在专页上区看到冲突编号；等第一笔出结论后，中区清空、下区出现第一笔；再投同名 → 收下，历史栏仍是第一笔、在途栏是新一笔。流水按印张名可翻。
